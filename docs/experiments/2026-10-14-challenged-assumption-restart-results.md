The five continuation cases finished with real isolated **gpt-6-luna / medium** agents. Every case passed its required coordination coverage. Superpose routed the warning to the two tasks resting on P0, preserved uncertainty before checking, invalidated exactly those tasks after the confirmed contradiction, replaced their holders, retained their code/history, and left CSV's holder intact. Its false-alarm case kept every original session. These paths were observed through platform snapshots and actual provider presentation/interruption events.

The experiment does **not** establish that Superpose or fresh sessions improve task performance. One comparison cell was invalidated by an operator prompt error, and the product checker used an insufficiently specified diagnosis argument shape. The replacement brief also lacked the explicit function contracts from the initial briefing. These limitations are part of the result.

## Product measurement and useful failures

The supplied evidence file had `{ record, report, applied, trace, incidentFiles }`. The frozen checker called `diagnose(record, report)` directly. The README named an `evidence` parameter but did not explicitly specify its shape or the accepted confidence enum. All five implementations read the supplied wrapper. The original checker therefore rejected every diagnosis; this cannot be treated as a clean agent-performance result.

A separately labelled, read-only diagnostic passed the **same supplied wrapper** to every final implementation. All five returned the correct historical cause and left unchecked or moved bindings unresolved. Both A cases returned the full advertised identity and binding. B/Git-same also returned those fields, using confidence `confirmed`; the two fresh B cases returned confidence `high` and omitted the advertised identity/binding fields. Original scores were not rewritten, and this diagnostic is not a new comparative score.

There were behavior failures independent of that argument ambiguity. Both fresh B repairs made `recover` require historical proof that its documented runtime interface did not require. The Superpose B batch repair also reported completed jobs without invoking supplied callbacks; the independent execution probe observed zero callbacks. Existing accounting, ledger and CSV survived across every continuation case.

The fresh brief carried promises, scope, checked facts and code, but did not explicitly carry the function contracts or direct the initial document-reading step. The old conversations had already read them. That prevents isolating the benefit of clearing an incorrect premise. The observations support preserving task contracts and independently validated behavior in a replacement projection; they do not establish a model-quality or platform winner.

## Repairs after the observed pilot

The current benchmark now declares **contract version 2**. Diagnosis accepts the supplied evidence wrapper; its successful output and confidence enum are explicit. Runtime recovery's normalized cause-only interface is distinguished from historical verification. Callback execution and eventual affordable completion are explicit. The same immutable contract text and source references are now carried in both original and replacement contexts.

The evaluator identifies itself as `cause-challenge-contract-v2`; its reference implementation uses that contract. Correct reference repairs and rejection controls pass in both worlds. A new no-model test creates an actually captured incident with both inflated cost and capacity refusal and verifies that it remains inconclusive, without a cause-selector flag. Focused qualification passed **26 tests** and typechecking. These repairs apply prospectively: no coding-agent rerun or new performance result was produced after them.
