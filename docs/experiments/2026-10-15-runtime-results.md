# Runtime changes with minimally instructed Codex agents

Superpose automatically detected the changed-service failure, delivered a verified finding to the affected workers, and those agents repaired it. Both control groups missed the change. Superpose did not complete the whole delivery: an unrelated CSV extension remained blocked in its older fork. No arm passed every final check. This is evidence that the automatic check-and-alert path works in this case, with a separate delivery configuration gap; it is not a general Superpose win or an estimate of the graph's advantage over ordinary CI.

Kevin required a vanilla control with no coordination guidance. Each control agent received exactly an ordinary feature request plus the project's normal requirements and interfaces. There was no instruction to coordinate, use Git, record assumptions, produce progress JSON, investigate the changed service or reset context. The optional-notes arm added only a pointer to an available notes directory, without a format. Native added the normal Superpose claim/tool pointer and actual product notices. The public README's inherited Git-delivery and separate-checkout instructions were removed before the source was frozen.

All nine sessions used gpt-6-luna / medium / standard tier with no model fallback. Every group had the same seed file contents and current-service data. Control agents shared a project folder within their group, with local work scored whether or not they committed. Superpose used its normal claim forks and shared line. Groups were isolated by network-free execution containers and a gateway that denied other-group routes; operator files, secrets and answers were outside their mounts. Three coding slots, fixed group order, two ordinary feature requests in the same sessions, no extra investigator or judge. The service changed between requests while the second tasks were pending. The operator supplied no diagnosis, answer or recovery coaching. Limits were 50 actions, seven minutes and $0.50 configured equivalent usage per role across both requests, and a 20-minute live ceiling. None of those limits caused a stop.

Superpose's first tasks passed and landed. After the service changed at 00:40:07.474 UTC, its actual Cloudflare check created verified finding f1 at 00:40:12.535: approximately 5.1 seconds. It was bound to code `b7ac335344f5541e421bed312ff1183e0c4d35e0` and input version 2, against the adopted executable article. Its affected set was c1/c2 (landed worker/retry work) and c4/c5 (their active extensions); CSV c3/c6 was excluded. The active worker and retry holders received the check output and stale notices with their next ordinary task at 00:40:13.370–371, approximately 5.9 seconds after rollout and 0.84 seconds after the finding. Provider user-message records and both agents' explicit acknowledgements establish receipt. The owner adapter published only observed public configuration; no diagnosis, finding, private oracle result or reference repair was sent to the product.

Both holders replanned and repaired the ambiguous refusal. The worker classified the legacy budget_limit response with transient markers as temporary capacity. The retry agent also adapted its path. Five feature claims landed. A current line check resolved f1 at 00:41:46.928. The final shared SHA was `d93f1ddccec73b496b0fb01ff7b1a0e63228de0a`; its check passed with input version 2 at that exact SHA. All ten final checks other than the missing report extension passed. No agent had to file an assumption or finding for the runtime failure to be detected and routed. No agent-authored finding was filed; the one finding was generated by the gate and retained after resolution.

CSV wrote and committed the requested report extension as `4e8504ffe6c6adcf36ffc7d047721a22a554fd04`, but could not finish c6. Its current-service test ran on its own older fork, whose worker still misclassified the response. The failure was outside CSV's scope. Its push was accepted as in scope and recorded as checks-failed; no pair verdict was reached. The CSV agent diagnosed the dependency and explicitly reported the unfinished claim. The observer did not finish, merge, repair or re-prompt that claim on its behalf. It remained claimed when the coding sessions closed, and the shared product correctly failed the report-extension check.

This exposed a configuration error in this setup: `superpose.json.check` included `constitution/*.test.mjs` in the standalone fork check, as well as running those articles on the combination. That prevents an unrelated old fork from reaching the combination check where it could benefit from a repair already on the shared line. The earlier qualification proved CSV was excluded from the alert; it did not test CSV's subsequent submission while its fork lacked the repair. This limits conclusions about delivery performance and is a concrete gap in the rehearsal, not evidence that the CSV feature was wrong. Product defaults and recovery behavior also need to make this situation hard to create and easy to recover from.

After the live run, a separate diagnostic copy merged the unchanged CSV commit with the repaired shared line cleanly and passed all 11 checks, with no model calls. It did not alter the pilot's graphs, refs, results or workspaces. That diagnostic isolates an integration/check configuration issue. It is not a successful delivery in the experiment. Before another coding run, qualify an unrelated old fork's own checks, its combination with both a broken and a repaired line, and its normal recovery and notification path. Keep fork unit tests distinct from the constitution on the combined code; do not assign a new conflict to an unrelated claim merely because the line already fails an article.

The narrower learning is that these models could repair the failure once the evidence reached them, while minimally instructed controls shipped plausible code without checking the changed runtime. Automatic verification and delivery supplied useful missing context. These arms bundle checks, branch/scoping rules, tool guidance, protected promises and routing. They do not isolate the value of graph routing from an ordinary automatic test failure notification. A future intermediate arm should provide ordinary current-service CI alerts without graph coordination, while retaining the minimally instructed vanilla arm. This pilot also did not test an unknown prose finding, isolated research groups, human article adoption, forced interruption or fresh-context recovery. Its significant finding was mechanically verified, and its important alert arrived with the next task.
